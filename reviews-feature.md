# reviews-feature.md — техплан блока "Отзывы"

Согласовано с Марией ранее в сессии: форма отзыва + горизонтальная карусель, публикация сразу без модерации, видно и посетителям, и Марии/Виктору (там же на сайте).

## Поля формы (уточнено Марией 2026-09-08)
1. Имя
2. Роль и площадка (пример: "арт-директор клуба ZION")
3. Текст отзыва

## Технический стек
GitHub Pages - чисто статический хостинг, своего сервера нет. Хранилище отзывов - **Firebase Firestore** (бесплатный план): форма пишет в базу напрямую из браузера через JS SDK, карусель читает базу в реальном времени и сразу показывает новый отзыв без перезагрузки страницы.

## Анти-спам (без модерации, раз публикация мгновенная)
Скрытое honeypot-поле (боты его заполняют, люди не видят) + ограничение длины текста + простая защита от повторной отправки подряд.

## Что нужно от Марии, когда дойдём до сборки этого блока
Завести бесплатный Firebase-проект под своим Google-аккаунтом (2-3 клика на firebase.google.com/console) и прислать оттуда конфиг-ключи - не секретные данные, по задумке Firebase публикуются прямо в коде сайта.

## Безопасность (обязательно при подключении, из аудита 2026-09-08)
1. **Рендер отзывов только через `renderReview()`** (уже написана в `index.html`, использует `textContent`/DOM-свойства, не `innerHTML`+конкатенация) - иначе вредоносный отзыв с `<script>`/`<img onerror>` внутри текста выполнится у каждого посетителя (stored XSS). Функция уже готова и прокомментирована прямо в коде рядом с `firebaseConfig`.
2. **Firestore Security Rules обязательны на стороне Firebase** (client-side `maxlength` - не защита, это просто UX): ограничить длину полей (`name`≤60, `role`≤90, `text`≤400), запретить любые поля кроме name/role/text/ts, запретить update/delete с клиента (только create), рассмотреть rate-limit по IP через Firebase App Check, если спам станет проблемой.
3. Сайт уже несёт `Content-Security-Policy` (см. `<meta>` в `<head>` `index.html`), `connect-src` заранее разрешает домены `*.googleapis.com`/`*.firebaseio.com`/`*.firebaseapp.com` под будущий Firestore SDK - при смене стека (не Firebase) политику надо будет поправить.

## Статус
Заложено в структуру (concept.md, секция 9). Реализация - на Фазе 6 (сборка), вместе с остальными экранами. Не блокирует сборку остального сайта. Клиентский код (форма + честное сообщение + безопасная функция рендера) готов и живой, ждёт только конфиг Firebase.
